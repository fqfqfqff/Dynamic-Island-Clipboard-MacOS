# Aura — план работ

macOS-приложение для кастомизации MacBook: живой вырез (Dynamic Island), менеджер
буфера обмена, полка файлов, зеркало уведомлений и открытый API для сторонних
интеграций.

Целевая машина: MacBook Air M4 (Mac16,12), macOS 26.5.1, Xcode 26.3, Swift 6.2.
Имя `Aura` и bundle id `dev.kekch.aura` — рабочие, переименовать можно в любой момент.

---

## 0. Ключевые архитектурные решения

**Одно приложение — menubar-агент.** `LSUIElement = true`, без иконки в Dock,
без главного окна. Всё живёт в вырезе и в строке меню.

**Сборка через SwiftPM, а не через .xcodeproj.** `swift build` + скрипт, который
собирает `.app` бандл. Причины: проект целиком в текстовых файлах (нормальные
диффы в git), сборка и запуск из терминала одной командой, Xcode при этом
открывает `Package.swift` и работает как обычно.

**Всё, что рисуется в вырезе — «активность».** Музыка, зарядка, таймер,
уведомление, копирование файла, прогресс сборки — один протокол `Activity`,
одна очередь `ActivityCenter`, одни правила приоритета и вытеснения. Это и есть
запрошенная «многозадачность»: несколько активностей живут одновременно,
компактно показываются по краям выреза и разворачиваются в полноценные карточки.

**Swift 5 language mode на старте.** Строгая конкурентность Swift 6 на каркасе
AppKit+SwiftUI отнимает больше времени, чем даёт. Переход на v6 — отдельная
задача в фазе 7, когда границы акторов устоятся.

## 1. Фазы

### Фаза 0 — каркас `[сделано]`
- `Package.swift`, `Info.plist`, скрипты `build.sh` / `run.sh`.
- Menubar-агент, пункт меню, выход.
- Ad-hoc подпись бандла.

### Фаза 1 — окно на вырезе `[сделано]`
- Вычисление геометрии выреза: `safeAreaInsets.top`, `auxiliaryTopLeftArea`,
  `auxiliaryTopRightArea`. Фолбэк на «виртуальный вырез» для машин и внешних
  мониторов без выреза.
- `NSPanel`: `.borderless` + `.nonactivatingPanel`, level `.statusBar + 1`,
  `collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary, .stationary]`,
  прозрачный фон, без тени.
- Три состояния: `collapsed` → `peek` (наведение) → `expanded` (клик).
- Точный hit-testing: окно большое и статичное, но клики принимает только
  текущая видимая форма — иначе оно перекрывает строку меню.
- `NotchShape` с вывернутыми верхними углами, чтобы панель «вытекала» из выреза.

### Фаза 2 — буфер обмена `[сделано: отдельное окно, поиск, персист, авто-вставка]`
- `ClipboardService`: таймер 0.25 с, сравнение `NSPasteboard.general.changeCount`.
  Пуш-уведомлений об изменении пастборда в macOS нет — только поллинг.
- Фильтр служебных типов: `org.nspasteboard.ConcealedType` (пароли из менеджеров),
  `TransientType`, `AutoGeneratedType`. Без этого история соберёт чужие пароли.
- Типы: текст, ссылка (отдельная карточка с доменом), картинка, файл, цвет.
- Дедупликация по хешу, лимит истории, закрепление (pin), поиск.
- Хранилище: сейчас история живёт в памяти (лимит 100 элементов) — этого хватает,
  пока нет персиста. Дальше: SQLite через GRDB, картинки и файлы на диск, в базе
  только ссылки.
- Глобальный хоткей `⌥⌘V` через Carbon `RegisterEventHotKey` (не требует
  Accessibility, в отличие от `NSEvent` мониторов).
- Вставка в активное приложение: синтез `⌘V` через `CGEvent` — **требует
  разрешения Accessibility**, запрашиваем при первом использовании.

### Фаза 3 — активности и многозадачность `[ядро, батарея, музыка, громкость, снимки экрана — сделано]`
- Протокол `Activity`: id, приоритет, компактное лево/право представление,
  развёрнутая карточка, время жизни.
- `ActivityCenter`: очередь, вытеснение по приоритету, склейка одинаковых,
  ограничение на число одновременных.
- Провайдеры:
  - **Батарея** — `IOPowerSources`, анимация при подключении кабеля.
  - **Громкость** — слушатель CoreAudio на устройстве вывода. Сделано.
    Системный HUD посреди экрана при этом остаётся: спрятать его можно только
    выгрузив системный процесс, Aura этого не делает.
  - **Яркость** — публичного API нет, отложено.
  - **Снимки экрана** — наблюдение за папкой снимков, превью в вырезе,
    перетаскивание файла прямо оттуда. Сделано.
  - **AirDrop / загрузки** — наблюдение за папкой Downloads через FSEvents.
  - **Музыка** — Музыка и Spotify через AppleScript, см. риск R1 ниже.
- Жест: горизонтальный свайп по вырезу переключает активности.

### Фаза 4 — уведомления
Два уровня, потому что единого легального API для чтения чужих уведомлений в
macOS нет (см. риск R2):
- **Уровень A, по умолчанию.** Accessibility-наблюдение за окнами процесса
  `com.apple.notificationcenterui`: `AXObserver` на создание окна, чтение
  `AXStaticText` (заголовок, подзаголовок, текст) + иконка приложения по bundle id.
  Требует только Accessibility, который уже нужен для вставки из буфера.
  Системный баннер при этом остаётся на экране — мы его дублируем, а не заменяем.
- **Уровень B, опционально.** Full Disk Access + чтение SQLite базы
  `group.com.apple.usernoted/db2/db`. Даёт полную историю и работает в режиме
  «Не беспокоить». Формат приватный, Apple может сломать его в любом обновлении —
  поэтому только как дополнение, с явным включением в настройках.
- Группировка по приложению, тихие типы, история за сутки.

### Фаза 5 — полка файлов (шелф)
- Drag & drop файла на вырез → файл «прилипает» к панели.
- Обратный drag из панели в любое приложение (`NSFilePromiseProvider`).
- Стопки, быстрая отправка в AirDrop, копирование пути.

### Фаза 6 — открытый API для интеграций `[сделано; CLI пока на python3]`
Именно это делает «полную интеграцию с приложениями» реальной: не мы
подстраиваемся под чужие приложения, а даём им способ показать себя в вырезе.
- Unix-сокет в `~/Library/Application Support/Aura/control.sock`, JSON-протокол.
- URL-схема `aura://activity/create?...` для скриптов и Shortcuts.
- CLI `aura` — обёртка над сокетом (сейчас python3, позже отдельный Swift-таргет):
  `aura activity push --title "Сборка" --progress 0.4 --icon hammer`
- Применение: прогресс `swift build`, статус CI, длинный `rsync`, рендер видео.

### Фаза 6.5 — производительность `[сделано 19 августа]`
Первая рабочая версия ела 16% процессора в простое и подвешивала систему.
Что чинилось:
- `NSAppleScript` компилировался заново на каждый опрос плеера — теперь
  скомпилированные скрипты кэшируются, интервал 3 секунды.
- Опросы накладывались друг на друга, если плеер отвечал дольше интервала —
  добавлен флаг занятости.
- Активность музыки перекладывалась в очередь каждые 2 секунды, запуская
  пружинную анимацию всего выреза — теперь только при смене трека или
  заметном сдвиге прогресса.
- `PulsingDot` анимировался бесконечно, то есть вырез перерисовывался 60 раз
  в секунду постоянно.
- `FullScreenWatcher` обходил все окна системы каждую секунду — теперь раз
  в три и только после дешёвой проверки строки меню.
- Движение мыши обрабатывалось на каждое событие — ограничено 30 Гц.
- `Text(date, style: .time)` в карточках буфера заводил самообновляемый таймер
  на каждую карточку.

Итог: 0% процессора в простое.

### Фаза 6.6 — аудит и тесты `[сделано 19 августа]`
Код разделён на `AuraCore` (библиотека) и `Aura` (точка входа), чтобы логику
можно было покрыть тестами. Добавлено 40 тестов.

Что нашёл и починил ручной разбор кода:
- Меню в строке состояния не открывалось: пункт `menu` подменялся на лету и
  сбрасывался раньше, чем меню успевало показаться. Из-за этого были
  недоступны настройки и выход. Теперь меню строится заново на каждый показ
  через `popUp`.
- Наблюдатель смены пространств добавлялся блоком, а снимался по `self`, то
  есть не снимался никогда.
- Превью снимка экрана поднимало в память весь файл целиком (снимок 3000×2000
  ≈ 24 МБ) ради картинки 96×96 — теперь ImageIO читает уменьшенную версию.
- История буфера хранила картинки в полном размере; теперь уменьшает до 320 px.
- `AXIsProcessTrusted` дёргался на каждой перерисовке окна буфера — закэширован.
- Опрос плеера мог залипнуть навсегда, если AppleScript не отвечал; добавлен
  таймаут. Запрет доступа больше не вечен — повторная попытка через две минуты.

Память в работе: 96 МБ → 65 МБ.

### Фаза 6.7 — оптимизация отклика `[в работе]`
Заметно на глаз и требует доводки:
- Полоса длительности двигается рывками: позиция приходит раз в три секунды.
  Нужно вести её локально между опросами, сверяясь с плеером изредка.
- Обложка и цвет появляются с задержкой в момент смены трека.
  Сделано: общий `CIContext` вместо создания на каждый вызов, и обновление
  карточки сразу после загрузки обложки, не дожидаясь следующего опроса.
- Опрос AppleScript остаётся самой дорогой частью. Стоит опрашивать чаще при
  раскрытой панели и реже — когда вырез свёрнут.

### Фаза 6.8 — производительность, второй заход `[19 августа]`

**Главное: бесконечная перерисовка.** Полоски эквалайзера хранили промежуточные
высоты в `@State` и обновляли их прямо во время отрисовки. SwiftUI на каждое
такое обновление перерисовывал вид заново — цикл без конца, ядро загружено
полностью. Замеры показывали 100% процессора в любом режиме, включая паузу.
Сглаживание перенесено в монитор спектра, состояния во время отрисовки больше
нет. Стало 6% при играющей музыке.

Заодно: `ps -o pcpu` показывает среднее за всё время жизни процесса, поэтому
для коротких запусков врёт — мерить нужно приростом `cputime` за интервал.

Что ещё сделано:
- анализ звука включается только когда что-то играет, экран не спит и
  приложение не на паузе;
- окно панели уменьшается до размеров выреза, когда она свёрнута: раньше
  оконный сервер обрабатывал прозрачную область 720×560 на каждом кадре;
- список аудио-процессов кэшируется на 1.5 секунды;
- опрос плеера: 4 секунды в покое, 1.5 при раскрытой панели;
- убран секундный таймер полноэкранного сторожа — то же состояние приходит
  событиями смены пространства;
- буфер обмена опрашивается 2 раза в секунду вместо четырёх.

**Что осталось в резерве.** При играющей музыке 6% — это цена живой
визуализации: полоски перерисовываются десять раз в секунду. Отключение
«полосок под реальный звук» в настройках даёт 4.5%. Дальнейшее сокращение
потребует рисовать полоски слоем Core Animation вместо SwiftUI.

### Правило, выученное трижды

Любое обращение к защищённым данным требует своего ключа в `Info.plist`,
и без него macOS не отказывает вежливо, а либо молчит, либо убивает процесс:

| Что | Ключ | Без ключа |
|---|---|---|
| Управление Музыкой и Spotify | `NSAppleEventsUsageDescription` | тихий отказ −1743, диалог не появляется |
| Анализ звука через тап | `NSAudioCaptureUsageDescription` | тихий отказ |
| Наушники и Bluetooth | `NSBluetoothAlwaysUsageDescription` | **падение процесса**, `TCC_CRASHING_DUE_TO_PRIVACY_VIOLATION` |

Прежде чем добавлять источник, который читает что-то системное, — сначала ключ.

## 2. Риски

**R1. Информация о проигрываемой музыке — проверено 19 августа 2026, закрыто.**
Приватный `MediaRemote.framework` подгружается и через `dlsym` отдаёт все
символы, но `MRMediaRemoteGetNowPlayingInfo` возвращает **пустой словарь**
любому обычному приложению — и с ad-hoc подписью, и с Developer ID.
Данные приходят только платформенным бинарям Apple (`Authority=Software
Signing`): именно поэтому `swift script.swift` показывает полные 14 ключей —
он исполняется внутри `swift-frontend`, подписанного Apple. Обход через
`osascript` (тоже Apple-подписанный) не работает: колбэк не приходит.

Решение: `MusicActivityProvider` через AppleScript к Музыке и Spotify.
Работает, требует разрешения Automation. Ограничение: видео в браузере и
прочие источники так не увидеть — это цена легального пути.

**R2. Уведомления.** Единого API нет, оба пути описаны в фазе 4. Уровень A
хрупок к изменениям вёрстки баннеров, уровень B — к изменению схемы базы.
*Действие: изолировать оба за одним протоколом `NotificationSource`, чтобы
поломка одного не тянула за собой UI.*

**R3. Сброс разрешений при пересборке.** TCC привязывает Accessibility к
подписи бандла. Ad-hoc подпись даёт новый CDHash при каждой сборке, поэтому
разрешение слетает после каждого `build.sh`.
*Действие: завести самоподписанный сертификат в keychain и подписывать им —
CDHash станет стабильным. До этого разрешение придётся выдавать заново.*

**R5. Разрешения TCC требуют трёх условий сразу — проверено на практике.**
Диалог «приложение хочет управлять…» не появится, если нарушено хоть одно:
- в `Info.plist` есть `NSAppleEventsUsageDescription` (без него система молча
  отвечает отказом −1743, и никакой `tccutil reset` не помогает);
- подпись стабильна (`Scripts/make-cert.sh`), иначе разрешение слетает при
  каждой пересборке;
- приложение лежит по постоянному пути (`Scripts/install.sh` → `~/Applications`),
  иначе переключатель в «Универсальном доступе» неактивен, потому что для
  системы это каждый раз новое приложение.

**R4. App Store закрыт.** Мониторинг пастборда + Accessibility + чтение чужих
уведомлений — гарантированный отказ на ревью. Распространение только прямое,
Developer ID + нотаризация, $99 в год.

## 3. Порядок работы

Фазы 0–2 дают приложение, которым уже можно пользоваться каждый день. Дальше
порядок гибкий, но фазу 6 стоит делать до фазы 4: собственный API проще, полезнее
и надёжнее, чем ковыряние в чужих уведомлениях.
