# Aura — состояние проекта

Документ для входа в контекст: что сделано, как устроено, обо что уже
спотыкались. Дополняет [PLAN.md](PLAN.md) (планы и риски) и

Репозиторий: `~/projects/aura`. Ветка `main`, все изменения закоммичены
локально. **На GitHub ничего не публиковалось** — владелец делает это сам.

---

## Что это

Приложение для MacBook: вырез камеры становится живым островком с плеером
и активностями, плюс менеджер буфера обмена. Swift 6, SwiftUI + AppKit,
без внешних зависимостей.

Машина разработки: MacBook Air M4, macOS 26.5.1, Xcode 26.3.
Bundle id `dev.kekch.aura`, установленная копия — `~/Applications/Aura.app`.

Объём: ~9000 строк кода, 86 тестов, 94 файла.

---

## Как работать

```bash
./Scripts/shots.sh         # снимки интерфейса в build/shots — без записи экрана
./Scripts/make-icon.sh     # перерисовать обложку приложения в Resources/Aura.icns
./Scripts/setup.sh         # полная установка с нуля: сертификат, сборка, заставка, автозапуск
./Scripts/install.sh       # пересобрать и обновить копию в ~/Applications
./Scripts/run.sh           # запустить из ./build для разработки
swift test                 # 86 тестов
Scripts/aura status        # диагностика: что работает и почему что-то нет
Scripts/aura showcase      # открыть витрину (и --close)
```

`Scripts/aura status` — главный инструмент отладки. Показывает видимость
панели, число активностей, состояние плеера с причиной отказа, доступность
уведомлений и фокуса, уровни спектра, право на вставку.

## Устройство

```
Sources/Aura/           точка входа (только она — остальное тестируемо)
Sources/AuraCore/
  App/                  делегат, меню в строке состояния, внешние команды
  Notch/                геометрия выреза, окно-панель, форма, состояния, вид
  Activities/           очередь активностей и все провайдеры
  Clipboard/            опрос пастборда, окно истории, журнал, вставка
  Showcase/             полноэкранная витрина и снимок для заставки
  Shelf/                файлы, брошенные на вырез
  Onboarding/           экран первого запуска с разрешениями
  Settings/             хранилище настроек, окно, тема
  System/               разрешения, хоткеи, спектр звука, сторожа
Sources/AuraSaver/      плагин заставки (отдельный бандл .saver)
Tests/AuraCoreTests/
```

**Ключевая абстракция — `Activity`.** Всё, что показывает вырез (музыка,
зарядка, наушники, встреча, уведомление, чужая задача), — это активность
с приоритетом. `ActivityCenter` держит очередь, вытесняет по приоритету,
убирает по истечении. Новый источник = новый провайдер, UI не трогается.

**Внешний API.** Сокет `~/Library/Application Support/Aura/control.sock`
(права 0600), URL-схема `aura://`, CLI `Scripts/aura`. Любой скрипт может
показать свою активность: `aura push --id build --title "Сборка" --progress 0.4`.

## Обо что уже спотыкались

Самое ценное в этом документе. Каждый пункт стоил отдельного расследования.

**1. Ключи `Info.plist` — три раза подряд.** Обращение к защищённым данным
без своего ключа не даёт вежливого отказа:

| Данные | Ключ | Без ключа |
|---|---|---|
| Управление плеерами | `NSAppleEventsUsageDescription` | тихий отказ −1743, **диалог не появляется вообще** |
| Тап аудио | `NSAudioCaptureUsageDescription` | тихий отказ |
| Bluetooth | `NSBluetoothAlwaysUsageDescription` | **падение процесса**, `TCC_CRASHING_DUE_TO_PRIVACY_VIOLATION` |
| Календарь | `NSCalendarsFullAccessUsageDescription` | отказ |

**2. MediaRemote закрыт.** Приватный фреймворк отдаёт «что играет» только
платформенным бинарям Apple (`Authority=Software Signing`). Проверка через
`swift script.swift` вводит в заблуждение: скрипт исполняется внутри
Apple-подписанного `swift-frontend` и данные получает. Обычное приложение
получает пустой словарь — с ad-hoc подписью и с Developer ID одинаково.

**3. Экран блокировки.** Рисовать там приложениям нельзя: при блокировке
скрывается вся сессия пользователя, уровень окна не помогает. Единственный
работающий путь — плагин заставки, её запускает система.

**4. `ps -o pcpu` врёт** на коротких запусках: это среднее за всё время жизни
процесса, включая тяжёлый старт. Мерить приростом `cputime` за интервал.

**5. Обновление `@State` во время отрисовки** = бесконечная перерисовка.
Так было со сглаживанием полосок: 100% процессора в любом режиме, включая
паузу. Промежуточные значения анимаций держать вне тела вида.

**6. Прозрачное окно поверх всего стоит дорого.** Окно 720×560 система
пересобирала на каждом кадре анимации полосок — половина всей нагрузки.
В покое окно сжимается до размеров выреза.

**7. Создание и удаление слоёв через `if` даёт рывок.** Слои оформления
должны существовать всегда и менять прозрачность — тогда переход ровный.

**8. Числа приходят в локали пользователя.** Spotify отдаёт позицию как
`87,094` — обычный `Double(_:)` возвращает nil, и полоса длительности
не появляется. Разбирать через `MusicResponse.number(_:)`.

**9. Кодировка буфера.** Текст, положенный консольными утилитами, приходит
разобранным в однобайтовой кодировке («привет» → «–њ—А–Є–≤–µ—В»).
`ClipboardService.repairEncoding` перебирает кодировки. `pbcopy` в тестах
портит кириллицу сам — проверять через `osascript`.

**10. Разрешения и подпись.** TCC привязывает разрешение к подписи и пути.
Ad-hoc подпись меняется при каждой сборке, `build/` пересоздаётся — поэтому
`Scripts/make-cert.sh` (стабильный сертификат) и установка в `~/Applications`.
Иначе ползунок в «Универсальном доступе» просто не двигается.

**11а. Изоляция теперь ломает сборку, а не прод.** В `Package.swift` у
AuraCore стоит `-Werror ActorIsolatedCall`: обращение к изолированному коду
из чужого потока — это не предупреждение, а падение у пользователя. Так уже
трижды умирала Aura (тап спектра, зонд уровня, разбор текстов песен), и все
три раза компилятор об этом честно предупреждал.

**11. Изоляция потоков.** IOBluetooth и AXObserver зовут колбэки со своих
потоков — колбэки помечены `nonisolated`, данные снимаются на месте и уходят
на главный поток значениями. Выполнение AppleScript изолировано в акторе.

**12. Замыкание в аудио-потоке роняло приложение при каждой музыке.**
`AudioDeviceCreateIOProcIDWithBlock` зовёт колбэк со своего потока CoreAudio.
Замыкание, созданное внутри класса под `@MainActor`, наследует его изоляцию —
Swift проверяет исполнителя на входе, проверка не проходит, процесс падает
с `SIGTRAP` в `_dispatch_assert_queue_fail`. Тап спектра открывается ровно
тогда, когда появляется звук, поэтому Aura умирала при включении музыки —
и выглядело это как «плеер работает криво». Лечится так: колбэк помечается
`@Sendable`, состояние выносится в отдельный `final class … @unchecked Sendable`,
и внутри нет ни одного обращения к `self`. Проверять только запуском:
компилятор молчит.

**13. Мёртвая зона наведения.** Окно перехватывало мышь по всей видимой форме
(вырез плюс компактные слоты, до +88 pt), а открывалось по зоне вокруг голого
выреза (+18 pt). Курсор, попавший в разницу, замораживал остров: события
движения не приходили ни от глобального монитора (они ушли «нам»), ни от
панели (`acceptsMouseMovedEvents` не выставлен, окно не key). Отсюда
«открывается только со второго раза». Зона наведения теперь считается от
видимой формы, у контейнера есть `NSTrackingArea(.activeAlways)`, а перехват
мыши решается после обработки движения, а не до.

**14. Содержимое раздувало форму острова.** В состоянии `peek` панель уже
собрана — прозрачная, но собранная, — и карточка плеера высотой под двести
точек растягивала контейнер. Чёрная форма заливала всё это целиком: от
наведения под вырезом разворачивался чёрный прямоугольник. Содержимое обязано
быть заперто в `contentSize` рамкой и `.clipped()`.

**15. `.aspectRatio(contentMode: .fill)` возвращает размер больше предложенного.**
Обрезание по форме считалось уже от раздутых границ картинки — отсюда цветная
кайма вокруг панели. Рамку ставить на саму картинку, до остальных слоёв.

**16. Liquid Glass поверх насыщенной картинки даёт радужную кромку.**
`glassEffect` преломляет то, что под ним; под ним была обложка с
`saturation(1.4)`. На чёрном и на градиенте этого не происходит.

**17. Баннер уведомления устроен не так, как кажется.** Живое окно отдаёт:

```
["Notification Center",                       ← заголовок окна
 "Телеграм, Никита, рабочий чат, привет",     ← сводка целиком
 "Никита", "рабочий чат", "привет"]           ← содержимое по узлам
```

Имя приложения есть **только в сводке**, первым элементом до запятой;
отдельного узла с ним нет. Разбор брал за приложение первый узел, то есть
буквально «Notification Center» — отсюда разом три поломки: не было иконки,
цвет откатывался к запасному, и уведомление никогда не помечалось
прочитанным, потому что сверять было не с чем. Смотреть живую структуру —
`Self.dump` в провайдере (временный, но восстанавливается за минуту).

**18. Диагностика через терминал ломает разрешения.** Запуск
`~/Applications/Aura.app/Contents/MacOS/Aura` из оболочки лишает процесс
Универсального доступа: TCC приписывает запрос родительскому процессу,
то есть терминалу. Приложение обязано запускаться через `open`, а
диагностика — писаться в файл: `NSLog` от неподписанного Apple процесса
в системном журнале виден не всегда.

**19. Одна осечка выключала прослушивание навсегда.** `AudioLevelProbe`
при любой неудаче создания тапа ставил `isBlocked` до перезапуска. Причин
временных хватает — процесс исчез между опросом и созданием тапа, система
занята, — и после одной такой осечки обычные приложения переставали
показываться совсем. Теперь повтор через 30 секунд, а код ошибки виден
в `aura status`.

**20. Тапу нужно время на раскрутку.** Агрегатное устройство отдаёт первые
буферы через пару секунд. Пока их нет, тишина в тапе ничего не значит —
а источник успевал попасть в немые и пропадал из выреза на весь карантин.
Поэтому «сколько слушать до вердикта» (4.5 с) отделено от «сколько длится
тишина» (2.5 с).

**21. Подвисание при раскрытии было четырьмя разными вещами сразу.**
Панель раскрывается — и в том же кадре: `isDetailed` переключался вызовом
`start()`, а тот начинался с `stop()`, который сносит тап уровня, подписки
на плееры, активность и сам `nowPlaying`; следом спектр глушил и заново
создавал агрегатное устройство CoreAudio; окно меняло размер синхронной
перекладкой всего дерева; и там же собиралось дерево карточки плеера.
Лечится разнесением по времени: режим подробности только переводит таймер,
а окно и содержимое готовятся заранее, по близости курсора.

**22. Раскрытая панель стоила вчетверо дороже, чем должна.** Два виновника.
`TimelineView` тикает даже при нулевой прозрачности — скрытые полоски
компактного вида перерисовывались десять раз в секунду, пока пользователь
смотрел на панель. И окно под панель было всегда 720×560, хотя сама панель
втрое меньше: прозрачное окно система пересобирает целиком, площадь
платится на каждом кадре. После правок 9.5% → 4.3%.

**23. Проект собирался только тем Xcode, что стоит на машине разработки.**
`#available(macOS 26.0, *)` — проверка во время работы, а `glassEffect` нужно
ещё и скомпилировать: в SDK младше macOS 26 такого метода нет вовсе. Локально
это незаметно, CI упал на первом же запуске. Лечится `#if compiler(>=6.2)` —
Swift 6.2 приехал вместе с Xcode 26 и этим SDK. Туда же: `CIContext` в старых
SDK не помечен `Sendable`.

**24. Строгая конкурентность строже с каждым Xcode.** То, что 26.3 считает
предупреждением, 26.6 считает ошибкой: замыкание, переданное в `@Sendable`
колбэк таймера, — это гонка, а `MainActor.assumeIsolated` рядом превращает
обещание в ложь. Помечать такие замыкания `@MainActor`: изолированное
глобальным актором Sendable по построению. **Вывод общий: зелёная сборка
на своей машине ничего не доказывает.**

**25. Тесты на переведённых строках зелёные только дома.** Машина сборки
говорит по-английски. Если тест проверяет текст, который проходит через
`t(...)`, язык нужно задать в самом тесте.

**26. У Spotify в AppleScript нет списка исполнителей.** В словаре ровно одно
текстовое поле `artist` (проверено по `sdef`), и для трека с несколькими
исполнителями оно называет только первого. Это ограничение Spotify, а не
разбора ответа. Остальных приходится брать с публичной страницы трека —
`og:description` вида «A, B · Альбом · Song · Год». Способ хрупкий, поэтому
результат принимается только если начинается с того, что уже сказал
AppleScript: сломается разметка — станет как было, а не пусто.

**27. Скрытое окно продолжает работать.** `orderOut` только убирает окно
с экрана — оно само, его `NSHostingView` и всё дерево SwiftUI внутри остаются
жить. Витрину достаточно было открыть один раз за сеанс, чтобы её три таймера
(строка песни, полоса времени, часы) тикали до перезапуска приложения.
В покое это стоило 1.29% процессора и 141 МБ против 0.10% и 81 МБ после
правки. При закрытии окна нужно снимать `contentView` и отпускать само окно.

**Как это ищется.** `sample <pid> 6 -file …` показывает главный поток
с именами функций проекта. Именно так и нашлось: в профиле «спящего»
приложения сидел `ShowcaseView.lyricsColumn`.

**28. Таймер, которому нечего делать, всё равно будит систему.** Очередь
активностей просыпалась дважды в секунду всегда, чтобы отфильтровать пустой
список. Периодическую работу заводить только тогда, когда есть предмет:
у загрузок — пока что-то качается, у истечения — пока есть срок.

**29. Измерять высоту содержимого внутри панели нельзя.** Высота содержимого
ограничена высотой панели, а высота панели считается от высоты содержимого —
измерение замыкается само на себя и возвращает ноль. Поэтому расчёт ведётся
по постоянным величинам, а разметка обязана их держать: числа лежат
в `ActivitiesPane` и оттуда же читает `NotchViewModel`.

**30. Падение при запуске чинится только из терминала.** Приложение не
успевает показать ни меню, ни настроек — выключить виновника изнутри нельзя.
Так было с падением на музыке: тап спектра открывался сразу, процесс умирал.
Поэтому `SafeMode` считает запуски, которые не дожили до двенадцатой секунды:
три подряд — и источники не поднимаются, а в меню появляется пункт вернуть их
обратно. Метка снимается по таймеру, а не при выходе, — иначе три случайных
падения за год сложились бы в аварийный режим.

**31. Расход в покое растёт незаметно, ловится только замером.** Глазами
разницы между 0.1% и 1.3% процессора нет. `Scripts/bench.sh` запускает
приложение, ждёт, пока оно успокоится, и сравнивает средний процессор и пик
памяти с бюджетом; тот же шаг стоит в CI. На раннере разрешений нет, поэтому
число там — нижняя граница: шаг ловит резкий рост, а не боевой расход.

**32. Долг по локализации нужно держать храповиком, а не обещанием.**
`LocalizationDebtTests` считает строки, зашитые в код мимо `t(…)`, и падает
в обе стороны: и когда их стало больше, и когда стало меньше — второе значит,
что порог пора опустить. Иначе перевод расходится с кодом на первой же спешке.

**33. Обработчик отмены `DispatchSource` не должен читать `self`.**
Отмена приходит асинхронно. Если к тому моменту слежение уже перезапустили,
`self.descriptor` указывает на новый дескриптор — и старая отмена закрывает
свежий. Источник остаётся живым, но смотрит в закрытый файл: ни событий,
ни ошибок. Так молча не работали снимки экрана — `applyProviderSettings()`
зовётся не один раз. Дескриптор нужно захватывать значением:
`let watched = descriptor; source.setCancelHandler { close(watched) }`.

**34. Тест, который заводит домен настроек с новым UUID, оставляет файл.**
Домен — это plist в `~/Library/Preferences`, и пишет его cfprefsd, когда ему
удобно; `removePersistentDomain` перед выходом из теста его не догоняет.
За сотни прогонов накопилось 3878 файлов. Домен на весь набор один —
`TestDefaults.make()`, — и очищается перед каждой выдачей.

**35. Тест не имеет права трогать то, чем пользуется человек.** Служба буфера
в тесте подняла настоящую историю пользователя, дописала в неё свои файлы
из `/var/folders` и выкинула из системного буфера то, что человек только что
скопировал. В тестах `persistClipboard`, `archiveEverything`
и `copyScreenshotToClipboard` выключаются, а запись в пастборд проверяется
на своём `NSPasteboard(name:)`, а не на общем.

**36. Опрос вместо события — самая частая лишняя работа.** Питание слушается
через `IOPSNotificationCreateRunLoopSource`, режим фокусирования — слежением
за файлом, буфер обмена замедляется, когда человека нет за компьютером.
Опрос остаётся только там, где события нет вовсе: у пастборда его в macOS
не существует, у плеера — тоже.

**37. Размывать нужно маленький слой, а не экран.** В витрине обложка
разворачивалась на весь экран, увеличивалась ещё в 2.6 раза и только тогда
размывалась радиусом 130. Промежуточные буферы под это уходят в гигабайты:
пик у процесса доходил до 4.5 ГБ, и после ночи с витриной приложение держало
286 МБ вместо 80. Порядок обратный — `frame(260) → blur(10) → scaleEffect(13)`:
те же 130 точек размытия в итоговом масштабе, но по слою в сотню раз меньше.
Полноразмерную обложку тоже не держим: Apple Music отдаёт до 3000×3000,
это 36 МБ на трек, а крупнее 640 её нигде не рисуют.

**38. Расход в покое смотреть только на прожившем приложении.** `ps %cpu` —
затухающее среднее за минуту, и у процесса, поднятого полминуты назад, в него
входит запуск: 1.14% против настоящих 0.02%. Память наоборот: сразу после
старта она честная, а проблемы видно через часы. Обе цифры теперь в
`aura status` вместе с возрастом процесса.

**39. Пустая строка содержится в любой.** Поиск приложения по имени
заканчивался нестрогим правилом `target.contains(candidate)`, а среди
запущенных всегда есть фоновые службы, чьё имя после нормализации пустое.
Совпадало первое попавшееся — и уведомление получало иконку `FollowUpUI`
вместо своей. Нестрогие правила теперь работают только на именах от четырёх
знаков.

**40. Имя в баннере — переведённое.** На русской системе он говорит
«Сообщения», а `CFBundleDisplayName` в бандле — «Messages». Искать нужно и по
`FileManager.displayName(atPath:)`, и по `localizedInfoDictionary`. А если
приложения на Маке нет вовсе — уведомления с айфона приходят и от таких, —
рисуется свой значок из первой буквы: пустое место в карточке хуже.

**41. Событие «переключились на приложение» приходит только при
переключении.** Сообщение пришло в Telegram, который и так впереди, — значок
не снимет никто, он висит до перезапуска. Поэтому через несколько секунд после
уведомления смотрим ещё раз: приложение всё ещё впереди — значит, прочитали.
Плюс срок жизни значка: то, на что не отреагировали за десять минут, уже
не новость.

**42. Событие «создано окно» приходит не на каждое уведомление.** Пока баннер
на экране, следующее сообщение система показывает в том же окне — просто
меняет в нём текст. Нового окна нет, `kAXWindowCreatedNotification` не
приходит, и всё, что пришло следом, терялось: остров не вырастал, превью
не появлялось. На живой проверке из трёх сообщений подряд доходило одно.
Поэтому, пока баннеры на экране, их содержимое перечитывается по таймеру —
работа живёт секунды, не осталось баннеров — обход останавливается сам.
Раскрытый центр уведомлений при этом отсеивается по числу узлов: в нём висят
виджеты, погода и биржа, и разбирать его как сообщение нельзя.

**43. Маска обрезает то, что вылезло за кадр.** Свечение обводки выходит
за кромку карточки на два десятка точек, а `.mask` ростом с кадр срезал его
ровной линией: подсветка выглядела наклейкой, а не светом. Увеличивать нужно
именно маску (`rimMask.padding(-bleed)`), а не сам слой обводки: раздуть слой
значит раздуть и форму выреза внутри него — она уедет от кромки. Проверено
буквально: при `padding` на слое обводка съехала вниз от карточки.

**44. Переведённое имя приложения лежит не в `Info.plist`.** В баннере имя
на языке системы — «Редактор скриптов», — а в `Info.plist` английское.
Перевод хранится отдельно: у современных приложений одной таблицей
`Contents/Resources/InfoPlist.loctable` со всеми языками сразу, у старых —
файлом на язык. Ни `FileManager.displayName(atPath:)`, ни
`localizedInfoDictionary` до него не добираются: они смотрят на язык нашего
процесса, а не на содержимое чужого бандла. Из-за этого иконки не находилось
ни у одного приложения с переводимым именем — Почта, Сообщения, Фото,
Календарь. Приложения индексируются под всеми своими именами сразу.

**45. Окно у карточки события и раскрытой панели общее.** Размер считался
только по панели, а карточка уведомления бывает шире — и её обрезало по бокам
вместе со свечением обводки. Ровно это выглядело как «срезанные края».

**46. Значка приложения в баннере нет как элемента.** Универсальный доступ
отдаёт только группу баннера и три строки текста:

    AXGroup      [1350,55 344×73]
      AXStaticText [1408,67 …]
      AXStaticText [1408,83 …]
      AXStaticText [1408,99 …]

Зато по ним место значка вычисляется однозначно: поле слева от текста,
квадрат по центру. Дальше — снимок этого квадрата через ScreenCaptureKit
и запись на диск. Это единственный способ показать иконку приложения,
которого на Маке нет: уведомления с айфона приходят и от таких.

**47. Признаку полноэкранного режима нужна выдержка.** Переключение рабочих
столов тремя пальцами на доли секунды прячет строку меню — а это и есть
дешёвый признак полноэкранного режима. Остров исчезал прямо посреди жеста
вместе с уведомлением. Выдержка 0.6 с закрывает жест; возврат остался
мгновенным.

**48. Угловой градиент не годится для бегущего света по вытянутой форме.**
Он крутится с постоянной угловой скоростью, а карточка длинная: по длинным
сторонам свет летел, по коротким полз. Отрезок контура (`trim`) идёт
с постоянной скоростью по длине пути — и выглядит ровно.

---

## Чего нет

- Названия треков из браузера — только заголовок вкладки, без обложки.
- Метаданных при AirPlay нет — виден факт воспроизведения и спектр.
- Режим фокусирования требует полного доступа к диску, иначе молчит.
- Автообновление только уведомляет, не ставит.
- Нет истории активностей, нет управления яркостью.
- Тестов на внешний вид нет. Виды рисуются offscreen (`Scripts/shots.sh`,
  `SnapshotRenderer`), так что сравнение с эталоном — вопрос одного шага,
  но эталонов пока нет.

## Если продолжать

По убыванию пользы:

1. **Snapshot-тесты на внешний вид** — рендер уже есть, нужны эталоны
   и сравнение. Половина правок в этом проекте была визуальной, и каждая
   проверялась глазами.
2. **Живая проверка того, что написано, но ни разу не сработало**: ответ
   из выреза на настоящем баннере, режим модема, импорт профиля, пипетка.
3. Управление яркостью, история активностей, прокрутка настроек поиском.
4. Нотаризация с Developer ID, если раздавать бинарник.
